# Using presets

A preset bundles a populating command, column-splitting rules, preview layouts, and custom keybindings into a self-contained TUI workflow.

## Downloading and listing presets

Fetch presets from the upstream repository into `~/.config/matchmaker/presets/` (or your platform's config directory) with `mm --download`:

```shell
# Download a preset collection folder
mm --download git

# Download a single top-level preset file
mm --download rg.toml

# Download all top-level presets
mm --download
```

<details>
<summary>How mm --download handles platform files, permissions, and LFS assets</summary>

When downloading a folder or file, `mm` filters platform-prefixed files (`linux.`, `macos.`, `unix.`, `win.`) to match your operating system and strips the prefix on disk. Helper scripts with a valid `#!` shebang and compiled helper binaries automatically receive executable permissions on Unix, and Git LFS data files (such as the compressed tables in `dict` and `unicode`) are fetched from the media endpoint.

</details>

List every installed preset on disk with `mm --presets`, or launch the interactive preset picker once `presets.toml` is downloaded:

```shell
mm --presets
mm -o presets
```

## Applying and layering presets

Pass `-o` (`--override`) to layer a preset onto your base `config.toml`. Relative names without a `.toml` extension resolve against your `presets/` directory (`<name>/main.toml`, `<name>.toml`, or the OS-prefixed variant), or you can pass an explicit `.toml` path:

```shell
mm -o rg
mm -o git/status
mm -o unicode
```

Multiple `-o` flags are applied in order from left to right, followed by any inline CLI overrides. Layering lets you combine a workflow preset with a **patch preset** (small partial overrides stored under `patches/` that tweak matcher behavior or binds without duplicating the base preset) or a color theme:

```shell
mm -o git/status -o patches/git-status
mm -o rg -o patches/frizbee
```

Launching a preset from `mm -o presets` also layers a matching `patches/<name>.toml` over it when one exists.

See [Options](/options) for how overrides merge.

### Shell aliases

For workflows you reach for often, wrap preset invocations (including layered patches and `--` forwarding) in shell aliases:

```shell
alias gl="mm -o git/restore --"
alias gs="mm -o git/status -o patches/git-status"
```

## Passing arguments

Arguments placed after `--` are forwarded as positional arguments (`"$@"`, `"$1"`, ...) to the preset's `start.command` and exposed to [templates](/template) as `{$0}`, `{$1}`, and so on:

```shell
mm -o git/restore -- src/
mm -o dict/en -- serendipity
mm -o bat_theme -- Cargo.toml
```

Trailing arguments take effect whenever `mm` executes `start.command` (when standard input is a terminal, or when `--no-read` is passed).

## In-picker help and navigation

Presets document themselves at runtime through two help actions:

| Key | Action | Output |
| --- | --- | --- |
| `F1` | `@help` | Fullscreen preset `README.md` (or leading `#` comment block) and resolved keymap in the [pager](/pager) |
| `alt-h` | `Help` | Resolved keymap in the preview pane |

Many multi-command and multi-preset workflows also bind `@next` (`alt-]`) and `@prev` (`alt-[`):

- When a preset defines `start.additional_commands` (such as `ps`, which switches between processes and open network sockets), `@next` and `@prev` cycle through those commands via `ReloadNext` and `ReloadPrev`.
- When a folder contains a ring of related pickers (such as `git` or `zellij`), `@next` and `@prev` transition between sibling presets in place via `BecomeSilent`.

### Standalone presets

Download a single-file preset with `mm --download <name>.toml` and launch it with `mm -o <name>`:

| File | Purpose |
| --- | --- |
| `presets.toml` | Interactive picker over installed presets (automatically layers matching `patches/<name>.toml` files) |
| `rg.toml` | Full-text search toggling live `ripgrep` queries (`ctrl-r`) and in-memory fuzzy filtering |
| `csv.toml` | RFC 4180 CSV and TSV viewer with a sticky header row and active-cell preview |
| `cargo-rx.toml` | Rust `Cargo.toml` example, binary, and compiled target runner |
| `man.toml` | Man page browser (`man -k`) with `batman` or `man` previews |
| `bat_theme.toml` | Interactive `bat` syntax theme previewer and config updater |
| `frizbee.toml` | Modifier preset switching the matcher backend to typo-tolerant `frizbee` (`max_typos = 1`) |
